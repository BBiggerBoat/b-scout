# B-Atlas Community Contributions — Phase 12

## Purpose

Phase 12 closes the initial contribution roadmap by letting actual submission behaviour inform future taxonomy changes. It does not add categories automatically.

## Feedback signals

The Contribution Review console now surfaces:

- total and unreviewed **Something else** submissions;
- submissions requiring clarification;
- recurring moderator-assigned **taxonomy signals**.

A taxonomy signal is a short reusable label such as `production changes`, `repower history`, or `layout identification`. It is stored on the reviewed contribution and aggregated in the admin console.

## Rule

**A recurring signal is a prompt for human review, not permission for automatic schema growth.**

Before adding a new visible contribution type, determine whether the need can be handled by:

1. a clearer existing field;
2. a structured subtype behind an existing user-facing choice; or
3. the existing Something else path.

Only create a new user-facing choice when repeated real submissions show that it materially reduces confusion or captures knowledge that cannot be normalized reliably otherwise.

## Recommended review cadence

During prototype use, review the Taxonomy feedback panel whenever the moderation queue is processed. No scheduled analytics or user tracking is required.

## Privacy

Taxonomy signals describe contribution content, not contributors. They must not contain names, emails, locations, or other personal data.

## Phase 12 exit criteria

- Something else usage is measurable.
- Clarification outcomes are measurable.
- Moderators can record reusable taxonomy-gap signals.
- Recurring signals are surfaced without automatic taxonomy mutation.
- The contribution taxonomy remains deliberately stable until real evidence justifies a change.
